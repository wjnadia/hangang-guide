# Claude Code

Claude Code는 Anthropic에서 제공하는 AI 코딩 도구로, 한강 슈퍼컴퓨터에서 소스코드 작성, 수정, 오류 분석 및 개발 작업을 지원합니다. 본 문서에서는 Claude Code의 기본 사용 방법과 한강에서 적용되는 안전 설정 및 주의사항을 안내합니다.

{% hint style="warning" %}
**베타서비스 운영 안내**

한강에서 제공하는 Claude Code의 관리형 안전 설정과 이용 제한은 베타서비스 운영 기간 중 적용되는 사항입니다. 시스템 부하 및 운영 상황에 따라 일부 설정이 변경될 수 있으며, 정식서비스 전환 시 운영 결과를 반영하여 최종 기준이 결정될 수 있습니다.
{% endhint %}

### 가. Claude Code 개요

Claude Code는 대규모 언어 모델(LLM)을 기반으로 소스코드를 분석·수정하고, 명령 실행과 테스트를 지원하는 CLI 기반 AI 코딩 도구입니다. 사용자의 작업 디렉터리에서 파일을 읽고 수정하며, 실행 결과에 따라 후속 작업을 수행할 수 있습니다.

한강에서는 프로그램 개발, Slurm 작업 스크립트 작성, 실행 오류 분석 및 코드 개선 등에 활용할 수 있습니다. 로그인 노드와 공유 파일시스템을 사용하는 일반적인 원칙은 [AI 코딩 도구 활용 안내](./) 페이지를 참고하시기 바랍니다.

Claude Code의 다양한 기능과 세부 사용법은 [Claude Code 공식 사용 설명서](https://code.claude.com/docs/ko/overview)를 참고하시기 바랍니다.

### 나. Claude Code 실행 및 인증

#### 1. 실행 환경

한강에서는 SSH로 로그인 노드에 접속하여 Claude Code CLI를 사용할 수 있습니다. 접속 방법은 [사용자 환경](https://docs-ksc.gitbook.io/hangang-user-guide/system/user-experience)을 참고하시기 바랍니다.

한강에서는 Claude Code의 시스템 공용 설치를 제공하지 않으므로 사용자가 자신의 홈 디렉터리에 설치하여 사용해야 합니다. GPU 로그인 노드와 CPU 로그인 노드는 홈 디렉터리를 공유하지만 CPU 아키텍처가 서로 다르므로, 설치한 실행 파일이 다른 노드에서 동작하지 않을 수 있습니다.

먼저 다음 명령으로 현재 아키텍처와 Claude Code 실행 파일을 확인합니다.

```
uname -m
command -v claude
claude --version
```

설치 및 실행 환경에 문제가 있는 경우에는 다음 명령으로 확인할 수 있습니다.

```
claude doctor
```

기관에서 정한 최소 지원 버전보다 낮은 Claude Code는 실행되지 않으며, 이 경우 업데이트가 필요합니다. 최소 지원 버전은 운영 상황에 따라 변경될 수 있습니다.

설치 및 업데이트에 관한 자세한 사항은 [Claude Code 공식 설치 안내](https://code.claude.com/docs/ko/overview)를 참고하시기 바랍니다.

#### 2. 사용자 인증

Claude Code를 사용하려면 별도의 Claude 서비스 이용 권한이 필요합니다. 한강 사용자 계정과 Claude 계정의 인증 및 이용 권한은 별도로 관리됩니다.

처음 실행하는 경우 다음 명령으로 시작합니다.

```
claude
```

인증되지 않은 상태에서는 로그인 절차가 안내됩니다. 한강 로그인 노드는 일반적으로 웹 브라우저를 실행하지 않는 환경이므로, 터미널에 표시되는 인증 URL을 사용자 PC의 웹 브라우저에서 열어 인증을 진행할 수 있습니다.

인증 상태 확인과 로그아웃은 다음 명령을 이용합니다.

```
claude auth status
claude auth logout
```

Anthropic API를 이용하는 경우에는 별도의 API 인증정보가 필요하며, 사용량에 따라 요금이 발생할 수 있습니다. API 키와 인증 토큰을 다른 사용자와 공유하거나 프로젝트 파일 및 Git 저장소에 포함하지 않도록 주의해야 합니다.

#### 3. Claude Code 실행

작업할 프로젝트 디렉터리로 이동한 후 Claude Code를 실행합니다.

```
cd /scratch/$USER/my-project
claude
```

위 경로는 예시이며 실제 사용자의 프로젝트 디렉터리로 변경해야 합니다. Claude Code는 실행한 디렉터리를 기준으로 프로젝트 파일을 분석하고 수정할 수 있으므로, 중요한 원본 데이터나 변경해서는 안 되는 파일은 작업 공간과 구분하여 관리하는 것이 좋습니다.

Claude Code는 VS Code 등 원격 개발 환경에서도 사용할 수 있습니다. **Claude Code가 한강 로그인 노드에서 실행되면 한강의 관리형 설정이 적용되며, 사용자 PC에서 실행되면 한강 로그인 노드의 관리형 설정이 적용되지 않습니다.**

원격 개발 도구의 사용 가능 여부는 한강의 SSH 및 OTP 인증 방식에 따라 달라질 수 있습니다. 원격 개발 환경의 상세 설정 방법은 [Claude Code 공식 문서](https://code.claude.com/docs/ko/overview)를 참고하시기 바랍니다.

### 다. 기본 사용 및 세션 관리

#### 1. 기본 명령어

Claude Code는 대화형 세션을 통해 작업을 수행하며, 이전 세션을 다시 불러오거나 새로운 세션을 시작할 수 있습니다.

| 명령어                 | 설명                    |
| ------------------- | --------------------- |
| `claude`            | 새로운 Claude Code 세션 시작 |
| `claude --continue` | 최근 세션 이어서 실행          |
| `claude --resume`   | 이전 세션을 선택하여 이어서 실행    |
| `/clear`            | 현재 대화 컨텍스트 초기화        |
| `/compact`          | 대화 내용을 요약하여 컨텍스트 정리   |
| `/status`           | 실행 환경 및 설정 상태 확인      |
| `/help`             | 사용 가능한 명령어 확인         |

이전 작업을 이어서 수행하려면 `claude --continue` 또는 `claude --resume`을 사용할 수 있습니다.

한강에서는 관리형 설정에 따라 오래된 세션 기록이 자동으로 정리될 수 있습니다. 보관 기간은 운영 상황에 따라 변경될 수 있으므로, 중요한 분석 결과와 작업 내용은 대화 기록에만 의존하지 말고 별도의 파일로 저장하는 것이 좋습니다.

#### 2. 파일 참조 및 컨텍스트 관리

Claude Code는 `@` 기호를 이용하여 특정 파일이나 디렉터리를 참조할 수 있습니다.

```
@train.py 파일의 분산학습 초기화 부분을 분석해 줘.

@job.slurm 파일의 자원 할당 설정을 검토해 줘.
```

필요한 파일을 명확히 지정하면 불필요한 파일시스템 탐색을 줄이고 작업에 필요한 정보를 정확하게 제공할 수 있습니다.

많은 대화 내용과 로그가 누적되는 경우에는 `/compact`를 이용하여 컨텍스트를 요약할 수 있으며, 새로운 작업을 시작할 때에는 `/clear`로 대화 컨텍스트를 초기화할 수 있습니다.

세션 및 컨텍스트 관리에 관한 자세한 내용은 [Claude Code CLI 참조](https://code.claude.com/docs/ko/cli-reference)를 참고하시기 바랍니다.

### 라. 프로젝트별 설정 및 CLAUDE.md

#### 1. CLAUDE.md 활용

Claude Code는 `CLAUDE.md` 파일을 통해 프로젝트 구조, 개발 환경 및 반복적으로 필요한 작업 지침을 참고할 수 있습니다.

프로젝트 디렉터리에서 Claude Code를 실행한 뒤 `/init` 명령을 이용하면 초기 `CLAUDE.md` 파일을 생성할 수 있습니다.

```
/init
```

생성된 파일에는 디렉터리 구조, 빌드 및 실행 방법, 사용하는 라이브러리, 테스트 절차 및 수정 가능한 파일 범위 등을 기록할 수 있습니다.

한강에서 사용할 프로젝트 지침에는 다음과 같은 내용을 포함하는 것을 권장합니다.

```
# Project Instructions

## Environment
- System: KISTI HANGANG
- Scheduler: Slurm

## Development
- Preserve the existing software environment.
- Do not run heavy workloads on login nodes.
- Avoid broad searches on shared filesystems.
- Confirm before submitting or cancelling Slurm jobs.

## Verification
- Review changes before running tests.
- Use small test cases before large jobs.
- Report modified files and test results.
```

특정 파티션 이름이나 작업 시간처럼 운영 상황에 따라 변경되는 값을 프로젝트 지침에 고정하기보다 실제 시스템 설정과 최신 사용자 지침서를 확인하도록 작성하는 것이 좋습니다.

#### 2. 사용자 및 프로젝트 설정

Claude Code는 사용자별 설정과 프로젝트별 설정을 지원합니다.

| 설정 파일                     | 용도                  |
| ------------------------- | ------------------- |
| `~/.claude/CLAUDE.md`     | 사용자 공통 작업 지침        |
| 프로젝트의 `CLAUDE.md`         | 프로젝트별 작업 지침         |
| `~/.claude/settings.json` | 사용자별 Claude Code 설정 |
| `.claude/settings.json`   | 프로젝트에서 공유하는 설정      |

한강에서는 사용자 및 프로젝트 설정과 별도로 기관의 관리형 안전 설정을 적용합니다. 사용자가 작성한 설정이나 `CLAUDE.md`는 관리형 설정을 보완하기 위한 것으로, 해당 설정을 변경하거나 우회하는 용도로 사용할 수 없습니다.

`CLAUDE.md`의 상세 작성 및 관리 방법은 [Claude Code 프로젝트 지침 공식 문서](https://code.claude.com/docs/ko/memory)를 참고하시기 바랍니다.

### 마. 권한 및 안전 설정

#### 1. 실행 권한 모드

Claude Code는 명령 실행과 파일 변경에 대한 사용자 승인 방식을 설정할 수 있습니다.

| 모드            | 설명                          |
| ------------- | --------------------------- |
| `default`     | 필요한 명령 실행과 파일 수정에 사용자 승인 요청 |
| `plan`        | 코드 분석과 작업 계획 검토를 중심으로 수행    |
| `acceptEdits` | 일부 파일 수정 작업을 자동 승인          |

한강에서는 **`auto`와 `bypassPermissions` 모드를 사용할 수 없습니다.** `default`, `plan`, `acceptEdits` 모드는 사용할 수 있으며, `acceptEdits`는 일부 파일 수정 작업을 자동 승인하므로 사용 시 주의해야 합니다.

일반적인 개발 작업에서는 `default` 모드를 권장하며, 코드 변경 전에 계획을 검토하려는 경우에는 `plan` 모드를 활용할 수 있습니다.

```
claude --permission-mode plan
```

실행 중에는 `/permissions` 명령으로 현재 권한 설정을 확인할 수 있습니다.

#### 2. 샌드박스

Claude Code는 지원되는 환경에서 운영체제 수준의 샌드박스(Sandbox)를 이용하여 명령의 파일시스템 및 네트워크 접근 범위를 제한할 수 있습니다.

그러나 **한강에서는 Claude Code 샌드박스를 관리형으로 적용하지 않고 있습니다.** 로그인 노드 환경에 따라 필요한 구성요소가 준비되지 않아 `/sandbox` 기능을 사용할 수 없을 수도 있습니다.

```
/sandbox
```

한강의 Claude Code는 관리형 권한 모드 및 사용자 승인으로 명령 실행을 제어합니다. 이러한 설정이 모든 명령에 대한 운영체제 수준의 격리를 보장하는 것은 아니므로, 실행하려는 명령과 변경 대상 파일을 확인해야 합니다.

#### 3. 서브에이전트 및 Workflow 제한

Claude Code는 복잡한 작업을 여러 하위 작업으로 나누고 별도의 서브에이전트(Subagent)가 수행하도록 지원합니다.

한강에서는 로그인 노드와 공유 파일시스템의 부하를 관리하기 위해 서브에이전트의 동시 실행 수와 생성 깊이를 제한하고 있습니다. 해당 제한값은 운영 상황에 따라 변경될 수 있으며, 여러 에이전트가 동일한 파일을 동시에 수정하지 않도록 작업 범위를 구분하는 것이 좋습니다.

또한 **한강에서는 Workflow 기능을 사용할 수 없습니다.** 해당 기능은 관리형 설정을 통해 비활성화되어 있으며, 다른 실행 방식으로 제한을 우회해서는 안 됩니다.

#### 4. 한강 운영 지침

다음은 Claude Code가 따르도록 제공되는 한강의 운영 지침입니다. **아래 명령이나 작업이 모두 기술적으로 자동 차단되는 것은 아닙니다.**

* 공유 파일시스템 상위 디렉터리의 광범위한 탐색 자제
* 로그인 노드에서 장시간·고부하 작업 실행 방지
* 제한 없는 병렬 빌드 및 불필요한 백그라운드 작업 방지
* Slurm 작업 제출·취소 전 사용자 확인
* 반복적인 작업 실패 시 자동 재제출 방지
* 다른 사용자의 파일 및 인증정보 접근 방지
* 기관의 안전 설정을 우회하는 작업 방지

이 지침은 Claude Code의 작업 방식을 안내하기 위한 것으로, 기술적으로 강제되는 권한 모드·서브에이전트·Workflow 제한과는 구분됩니다.

로그인 노드, 공유 파일시스템 및 Slurm의 자세한 사용 원칙은 **AI 코딩 도구 활용 안내**를 참고하시기 바랍니다. 권한 설정에 관한 자세한 기능은 [Claude Code 권한 구성 공식 문서](https://code.claude.com/docs/ko/permissions)에서 확인할 수 있습니다.

### 바. Claude Code 활용 예제

#### 1. 소스코드 분석

Claude Code를 이용하여 기존 프로그램의 구조와 주요 함수의 역할을 분석할 수 있습니다.

```
@src/ 디렉터리의 코드 구조를 분석하고
MPI 초기화와 통신을 담당하는 부분을 정리해 줘.

코드는 수정하지 말고 분석 결과만 설명해 줘.
```

공유 파일시스템의 상위 디렉터리를 탐색하도록 요청하기보다 분석할 프로젝트와 파일 범위를 명확하게 지정하는 것이 좋습니다.

#### 2. Slurm 작업 스크립트 검토

Claude Code는 기존 Slurm 작업 스크립트의 자원 할당과 실행 명령을 검토할 수 있습니다.

```
@job.slurm 파일을 검토해 줘.

한강 사용자 지침서의 Slurm 사용 방법과 비교하여
잘못된 옵션이나 개선할 부분을 설명해 줘.

실제 작업은 제출하지 말고
수정이 필요한 부분만 제안해 줘.
```

Claude Code가 제안한 Slurm 옵션은 현재 시스템에서 지원되는지 확인해야 합니다. 실제 작업을 제출하기 전에 변경사항을 검토하고 작은 시험 작업으로 정상 동작을 확인하는 것을 권장합니다.

#### 3. 프로그램 오류 분석 및 수정

프로그램이 정상적으로 실행되지 않는 경우에는 작업 스크립트와 오류 로그를 함께 제공하여 원인을 분석할 수 있습니다.

```
@job.slurm 작업이 실행 직후 종료되었습니다.

오류 로그를 분석하여 가능한 원인을 우선순위별로 정리해 줘.

기존 실행 환경을 유지하면서 최소한의 수정사항과
검증 방법을 제안해 줘.

새로운 Slurm 작업은 제출하지 마.
```

코드를 수정한 경우에는 변경사항을 검토하고 작은 입력 데이터로 정상 동작을 확인한 뒤 실제 계산 작업에 적용하는 것이 좋습니다.

### 사. 문제 해결 및 주의사항

#### 1. 주요 문제 및 확인 방법

| 증상                          | 확인 사항                        |
| --------------------------- | ---------------------------- |
| `claude: command not found` | 사용자 설치 여부 및 PATH 설정          |
| Claude Code 실행 불가           | 시스템 아키텍처 및 실행 파일 호환성 확인      |
| 최소 지원 버전 안내와 함께 실행 거부       | Claude Code 업데이트             |
| 로그인 또는 인증 실패                | Claude 계정 이용 권한 및 인증 상태 확인   |
| 명령 실행이 제한됨                  | 현재 권한 모드와 관리형 설정 확인          |
| `/sandbox` 사용 불가            | 샌드박스 지원 여부 및 실행 환경 확인        |
| Workflow 기능 사용 불가           | 한강 관리형 설정에서 비활성화된 기능인지 확인    |
| 이전 세션을 찾을 수 없음              | 작업 디렉터리와 세션 기록 정리 여부 확인      |
| 원격 환경에서 설정이 다름              | Claude Code가 실제로 실행되는 호스트 확인 |

설치 및 실행 환경에 문제가 있는 경우에는 `claude doctor`와 `/status` 명령으로 상태를 확인할 수 있습니다.

관리형 설정으로 제한된 기능은 사용자 설정이나 별도 실행 방법으로 우회해서는 안 됩니다.

#### 2. 이용 시 주의사항

Claude Code는 사용자의 계정과 권한으로 파일을 수정하고 명령을 실행합니다. 따라서 중요한 파일이나 연구 데이터가 의도하지 않게 변경되지 않도록 관리하고, 실행 결과의 정확성과 성능을 검증해야 합니다.

대규모 디렉터리 탐색, 반복적인 Slurm 작업 제출, 장시간 백그라운드 실행 및 다수의 서브에이전트 실행은 공유 시스템에 영향을 줄 수 있으므로 주의해야 합니다.
