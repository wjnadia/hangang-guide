# AI 코딩 도구 활용 안내

한강 슈퍼컴퓨터에서 Claude Code, Codex 등 AI 코딩 도구를 사용하는 방법과 이용 시 주의사항을 안내합니다.

{% hint style="warning" %}
**베타서비스 운영 안내**

본 지침에서 안내하는 AI 코딩 도구의 이용 기준 및 안전 설정은 베타서비스 운영 기간 중 적용되는 사항입니다. 시스템 부하 및 운영 상황에 따라 일부 설정과 이용 제한이 변경될 수 있으며, 정식서비스 전환 시 운영 결과를 반영하여 최종 기준이 결정될 수 있습니다.
{% endhint %}

### 가. AI 코딩 도구 개요

AI 코딩 도구는 대규모 언어 모델(LLM)을 기반으로 소스코드 작성, 수정, 오류 분석 및 테스트 등의 개발 작업을 지원하는 도구입니다. 일반적인 대화형 AI와 달리 사용자의 작업 환경에서 파일을 읽거나 수정하고 명령을 실행하며, 실행 결과에 따라 후속 작업을 수행할 수 있습니다.

한강에서는 Claude Code와 Codex를 이용하여 프로그램 개발, Slurm 작업 스크립트 작성, 실행 오류 분석 및 코드 개선 등에 활용할 수 있습니다. 다만 AI 코딩 도구는 사용자의 계정과 권한으로 동작하므로, 수행하는 명령과 변경사항을 확인하고 실행 결과의 정확성과 안전성을 검증해야 합니다.

### 나. 주요 기능 및 활용 분야

#### 1. 주요 활용 분야

| 활용 분야       | 주요 기능                               |
| ----------- | ----------------------------------- |
| 코드 작성 및 수정  | Python, C/C++, CUDA 등의 소스코드 작성 및 개선 |
| 작업 스크립트 작성  | Slurm 작업 스크립트 작성과 자원 할당 설정 검토       |
| 오류 분석 및 디버깅 | 컴파일 오류, 실행 로그 및 작업 상태 분석            |
| 코드 변환 및 최적화 | 스크립트 변환, 병렬 프로그램 개선 및 코드 구조 정리      |
| 테스트 및 검증    | 테스트 코드 작성, 실행 결과 비교 및 동작 검증         |
| 문서 작성       | README, 프로그램 설치 방법 및 사용 예제 작성       |

Claude Code와 Codex는 명령줄 인터페이스(CLI)를 통해 사용할 수 있어 SSH, Shell, Git 및 Slurm 등을 사용하는 기존 슈퍼컴퓨팅 개발 환경과 연계할 수 있습니다. 특히 관련 파일과 오류 로그를 지정하여 분석하고, 작은 단위로 수정 및 검증을 반복하는 작업에 유용합니다.

#### 2. 서브에이전트 활용

일부 AI 코딩 도구는 복잡한 작업을 여러 하위 작업으로 분리하고 별도의 서브에이전트(Subagent)가 병렬로 수행하도록 지원합니다. 예를 들어 소스코드 분석, 오류 로그 확인 및 테스트 코드 작성 등을 분담할 수 있습니다.

다만 여러 에이전트를 동시에 실행하면 CPU 사용량과 공유 파일시스템 접근이 증가할 수 있습니다. 한강에서는 일부 도구에 서브에이전트 동시 실행 수와 생성 깊이 제한을 적용하고 있으며, 해당 설정은 운영 상황에 따라 변경될 수 있습니다.

여러 에이전트가 동일한 파일을 동시에 수정하지 않도록 작업 범위를 구분하고, 최종 변경사항은 사용자가 직접 확인하는 것을 권장합니다.

### 다. 한강 사용 환경 및 안전 설정

#### 1. 관리형 안전 설정

한강에서는 다수의 사용자가 공유하는 시스템의 안정적인 운영을 위해 Claude Code와 Codex에 관리형 안전 설정을 적용하고 있습니다.

<table data-header-hidden><thead><tr><th></th><th></th></tr></thead><tbody><tr><td>구분</td><td>주요 적용 내용</td></tr><tr><td rowspan="2">Claude Code</td><td>권한 확인 생략(<code>bypassPermissions</code>) 및 <code>auto</code> 모드 사용 제한</td></tr><tr><td>Workflow 기능 비활성화, 서브에이전트 동시 실행 수·생성 깊이 제한, 최소 지원 버전 적용</td></tr><tr><td>Codex</td><td>사용자 승인 정책과 샌드박스 모드의 관리형 제한</td></tr><tr><td>공통</td><td>로그인 노드, 파일시스템 및 Slurm 이용에 관한 운영 지침 제공</td></tr></tbody></table>

**관리형 안전 설정은 기술적으로 실행을 제한하는 기능과 에이전트에 전달하는 운영 지침으로 구분됩니다.** 운영 지침에 포함된 모든 명령이 자동으로 차단되는 것은 아니므로, 사용자는 에이전트가 수행하는 작업을 확인해야 합니다.

관리형 설정은 한강에서 해당 프로그램이 실행되는 호스트를 기준으로 적용됩니다. 사용자 PC에서 실행되는 AI 코딩 도구에는 한강 로그인 노드의 관리형 설정이 적용되지 않습니다.

AI 코딩 도구가 실행한 작업은 사용자의 계정과 권한으로 수행되며, 사용자는 해당 작업과 결과를 확인하고 관리해야 합니다. 운영 지침을 우회하거나 시스템 안정성에 영향을 주는 작업은 관리자가 중지할 수 있으며, 필요한 경우 이용이 제한될 수 있습니다.

도구별 관리형 설정은 [Claude Code](claude-code.md) 및 [Codex](codex.md) 페이지를 참고하시기 바랍니다.

#### 2. 로그인 노드 이용

로그인 노드는 다수의 사용자가 공동으로 사용하는 환경으로, AI 코딩 도구를 이용한 코드 작성, 파일 수정, 경량 테스트 및 실행 로그 분석 등의 작업을 수행할 수 있습니다.

대규모 컴파일, MPI 병렬 실행, GPU 학습 및 추론, 대용량 데이터 처리 등 시스템 자원을 많이 사용하는 작업은 Slurm으로 계산 자원을 할당받아 수행해야 합니다. AI 코딩 도구가 실행하는 명령에도 동일한 원칙이 적용되며, 제한 없는 병렬 빌드나 장시간 백그라운드 작업은 피해야 합니다.

자세한 사항은 [사용자 환경](https://docs-ksc.gitbook.io/hangang-user-guide/system/user-experience) 및 [스케줄러(Slurm)를 통한 작업 실행](https://docs-ksc.gitbook.io/hangang-user-guide/system/slurm)을 참고하시기 바랍니다.

#### 3. 공유 파일시스템 이용

한강의 Lustre 파일시스템은 다수의 사용자가 공유하는 환경입니다. AI 코딩 도구가 광범위한 디렉터리를 탐색하면 많은 파일과 디렉터리에 대한 메타데이터 요청이 발생하여 다른 사용자의 작업에 영향을 줄 수 있습니다.

따라서 `/`, `/home01`, `/scratch`, `/appsdata` 등 파일시스템 상위 디렉터리 전체를 대상으로 `find`, `du`, `ls -R`, `grep -r`, `rg` 등을 실행하지 않아야 합니다. 이러한 탐색은 한 번만 수행해도 시스템에 부하를 줄 수 있으며, 현재 운영 지침만으로 모든 명령이 자동 차단되는 것은 아닙니다. 관리자는 시스템 부하를 모니터링하고 필요한 조치를 수행할 수 있습니다.

파일 검색은 사용자에게 필요한 프로젝트 디렉터리와 파일 범위를 지정하여 수행하는 것을 권장합니다.

```
cd /scratch/$USER/my-project
rg -n --glob '*.py' "target_function" ./src
```

파일시스템 사용량은 광범위한 디렉터리 탐색 대신 Lustre에서 제공하는 쿼터 조회 기능을 이용하는 것이 좋습니다. 파일시스템별 용도, 쿼터 및 보관 정책은 [사용자 환경](https://docs-ksc.gitbook.io/hangang-user-guide/system/user-experience)을 참고하시기 바랍니다.

#### 4. Slurm 작업 관리

AI 코딩 도구를 통해 계산 작업을 수행하는 경우에도 기존 Slurm 이용 원칙을 준수해야 합니다. 에이전트에는 새로운 작업을 제출하거나 기존 작업을 취소하기 전에 사용자에게 확인을 요청하도록 안내하고 있습니다. 이는 일반적인 작업 수행 지침이며, 모든 Slurm 명령의 실행을 자동으로 차단하는 정책은 아닙니다.

작업을 처음 실행하는 경우에는 작은 시험 작업으로 정상 동작을 확인한 뒤 작업 규모를 확대하는 것을 권장합니다. 동일한 작업이 반복적으로 실패하면 자동으로 재제출하기보다 오류 로그를 먼저 분석해야 하며, 작업 상태도 지나치게 짧은 간격으로 반복 조회하지 않도록 주의해야 합니다.

Codex는 현재 한강에서 사용하는 샌드박스 환경에서 Slurm 명령 실행이 제한될 수 있습니다. 자세한 동작과 승인 절차는 **Codex** 페이지를 참고하시기 바랍니다.

사용 가능한 파티션, 작업 시간, 자원 할당 및 제출 제한은 운영 상황에 따라 변경될 수 있습니다. 최신 기준은 [스케줄러(Slurm)를 통한 작업 실행](https://docs-ksc.gitbook.io/hangang-user-guide/system/slurm)을 참고하시기 바랍니다.

#### 5. 소프트웨어 및 컨테이너 환경

AI 코딩 도구가 제안하는 소프트웨어 설치 및 실행 명령은 한강의 실제 환경과 일치하는지 확인해야 합니다. 특히 GPU 로그인 노드와 CPU 로그인 노드는 서로 다른 CPU 아키텍처를 사용하므로, 실행 파일과 라이브러리의 호환성을 확인하는 것이 중요합니다.

AI 모델이 제안한 모듈이나 라이브러리 버전이 시스템에 존재한다고 가정하지 말고 `module avail`, `module list` 등으로 실제 환경을 확인해야 합니다.

컨테이너 이미지 빌드와 실행, AI 프레임워크 및 GPU 통신 환경은 다음 지침서를 참고하시기 바랍니다.

* [컨테이너](https://docs-ksc.gitbook.io/hangang-user-guide/system/container)
* [AI 프레임워크](https://docs-ksc.gitbook.io/hangang-user-guide/software/ai)
* [PyTorch](https://docs-ksc.gitbook.io/hangang-user-guide/software/pytorch)
* [NCCL 활용 및 Slingshot 연동](https://docs-ksc.gitbook.io/hangang-user-guide/software/nccl-slingshot)

#### 6. 보안 및 데이터 보호

AI 코딩 도구는 사용자의 권한으로 파일을 읽고 명령을 실행할 수 있으므로 인증정보와 연구 데이터 취급에 주의해야 합니다. 비밀번호, SSH 개인 키, API 토큰, 외부 공개가 제한된 연구 데이터 및 다른 사용자의 비공개 정보가 에이전트를 통해 노출되지 않도록 관리해야 합니다.

외부 AI 서비스를 사용하는 경우에는 프롬프트뿐 아니라 에이전트가 읽은 파일, 명령 실행 결과와 로그도 외부로 전송될 수 있습니다. 또한 외부에서 다운로드한 스크립트, 플러그인 및 MCP 서버는 출처와 실행 권한을 확인한 후 사용해야 합니다.

#### 7. 권한 및 샌드박스

AI 코딩 도구의 실행 권한 설정은 도구별로 다르게 구성됩니다.

**Claude Code**는 명령 실행과 파일 변경에 대한 권한 모드를 관리형으로 제한합니다. 한강에서는 일부 권한 모드를 사용할 수 없으며, Claude Code의 운영체제 수준 샌드박스는 관리형으로 활성화되어 있지 않습니다.

**Codex**는 샌드박스 모드와 사용자 승인 정책을 별도로 관리합니다. 한강에서는 읽기 전용(`read-only`)과 작업 공간 쓰기(`workspace-write`) 모드를 허용하고, 전체 접근 및 승인 절차 우회 방식을 제한합니다.

샌드박스는 시스템 자원에 대한 기술적 접근 제한이고, 사용자 승인은 특정 작업 실행 전에 사용자의 확인을 요청하는 절차입니다. 운영 지침에 따른 사용자 확인과 샌드박스의 기술적 제한은 서로 구분하여 이해해야 합니다.

자세한 설정과 실제 실행 시 주의사항은 각 도구의 사용 안내 페이지를 참고하시기 바랍니다.

### 라. AI 코딩 도구 사용 방법

#### 1. 권장 작업 절차

AI 코딩 도구는 하나의 요청으로 모든 작업을 수행하도록 하기보다 작은 단위로 나누어 결과를 검증하는 방식으로 사용하는 것이 좋습니다.

1. 작업 목표와 수정할 파일 및 범위를 명확히 지정합니다.
2. 관련 소스코드, 설정 파일 및 오류 로그를 제공합니다.
3. 변경 계획과 실행할 명령을 먼저 검토합니다.
4. 필요한 변경사항을 작은 단위로 적용합니다.
5. 실행 결과를 검증한 후 다음 작업을 진행합니다.

특히 Slurm 작업 제출, 대규모 컴파일 및 파일 삭제 등 시스템 자원이나 데이터에 영향을 주는 작업은 실행 전에 내용을 확인하는 것을 권장합니다.

#### 2. 효과적인 프롬프트 작성

AI 코딩 도구에 작업을 요청할 때에는 시스템 환경, 작업 목표, 관련 파일 및 제약조건을 구체적으로 설명하는 것이 좋습니다.

한강의 Slurm 설정이나 GPU 구성 등을 모델이 정확히 알고 있다고 가정하지 말고, 공식 사용자 지침서와 실제 시스템에서 확인한 정보를 기준으로 작업하도록 요청해야 합니다.

예를 들어 다음과 같이 요청할 수 있습니다.

> 한강에서 PyTorch 분산학습 프로그램을 실행하려고 합니다. 현재 작업 스크립트와 환경 설정, 오류 로그를 제공하겠습니다. 기존 환경을 유지하면서 오류를 해결할 최소한의 수정사항을 제안하고, 검증 방법을 설명해 주세요. 실제 Slurm 작업을 제출하기 전에는 확인을 요청해 주세요.

#### 3. 프로젝트별 지침 파일

AI 코딩 도구는 프로젝트별 지침 파일을 통해 작업 환경과 반복적으로 필요한 설정을 참고할 수 있습니다.

| 도구          | 프로젝트별 지침 파일 |
| ----------- | ----------- |
| Claude Code | `CLAUDE.md` |
| Codex       | `AGENTS.md` |

프로젝트 지침에는 디렉터리 구조, 빌드 및 실행 방법, 테스트 절차, 사용하는 라이브러리와 수정 가능한 파일 범위 등을 기록할 수 있습니다.

특정 파티션 이름이나 작업 시간처럼 변경되는 운영값을 고정하기보다는 실제 시스템 설정과 최신 사용자 지침서를 확인하도록 작성하는 것이 좋습니다. 자세한 사용법은 각 도구의 전용 페이지를 참고하시기 바랍니다.

#### 4. 변경사항 관리

AI 코딩 도구를 이용할 때에도 Git 등의 버전 관리 도구로 정상 동작하는 상태를 기록하고, 변경사항을 작은 단위로 적용하는 것을 권장합니다.

중요한 소스코드와 설정 파일을 수정한 뒤에는 변경 전후 차이를 확인하고, 컴파일 및 테스트 결과를 검증해야 합니다. 여러 에이전트가 작업한 결과를 결합할 때에도 파일 충돌과 의도하지 않은 변경이 없는지 확인하는 것이 좋습니다.

### 마. 한강 활용 예제

#### 1. Slurm 작업 스크립트 작성

AI 코딩 도구를 이용하여 Slurm 작업 스크립트를 작성하거나 기존 스크립트의 자원 할당 설정을 검토할 수 있습니다.

> 한강에서 GPU를 사용하는 Python 프로그램을 실행하려고 합니다. 최신 Slurm 사용자 지침서를 참고하여 작업 스크립트를 작성하고, 자원 할당 옵션과 실행 방법을 설명해 주세요. 실제 작업을 제출하기 전에 스크립트를 먼저 보여주세요.

에이전트가 작성한 스크립트는 현재 시스템의 자원 할당 기준에 맞는지 확인하고, 작은 시험 작업으로 정상 동작을 검증하는 것이 좋습니다.

#### 2. Slurm 작업 오류 분석

작업이 실패한 경우에는 작업 상태, 종료 코드 및 오류 로그를 이용하여 원인을 분석할 수 있습니다.

예를 들어 사용자가 터미널에서 다음 명령으로 기존 작업 정보를 확인할 수 있습니다.

```
sacct -j 1234567 --format=JobID,JobName,State,ExitCode,Elapsed
```

`1234567`은 예시 작업 번호이며, 실제 확인할 작업 번호로 변경해야 합니다.

이후 다음과 같이 요청할 수 있습니다.

> 기존 Slurm 작업의 상태와 종료 코드, 실행 로그를 제공하겠습니다. 가능한 오류 원인을 우선순위별로 정리하고 다음에 확인할 항목을 제안해 주세요. 새로운 작업을 제출하지 말고 기존 로그부터 분석해 주세요.

Codex 안에서 Slurm 명령을 실행할 때에는 샌드박스 제약이 적용될 수 있으므로, **Codex** 페이지의 안내를 확인하시기 바랍니다.

#### 3. 코드 분석 및 성능 개선

AI 코딩 도구는 기존 프로그램의 병렬화 구조를 분석하거나 성능 개선 방안을 제안할 수 있습니다. 다만 MPI, GPU 및 통신 라이브러리와 관련된 최적화는 실제 하드웨어와 실행 환경에 따라 결과가 달라질 수 있습니다.

제안된 변경사항은 작은 규모에서 정확성을 검증한 뒤, 동일한 조건의 성능 측정을 통해 효과를 확인하는 것이 좋습니다. 분산학습과 GPU 통신 환경에 관한 자세한 내용은 [PyTorch](https://docs-ksc.gitbook.io/hangang-user-guide/software/pytorch) 및 [NCCL 활용 및 Slingshot 연동](https://docs-ksc.gitbook.io/hangang-user-guide/software/nccl-slingshot)을 참고하시기 바랍니다.

### 바. 실행 결과 검증 및 주의사항

#### 1. AI 모델이 생성하는 코드의 한계

AI 모델은 일반적인 Linux 및 개발 환경을 바탕으로 명령과 설정을 제안하므로 한강의 실제 시스템 구성과 일치하지 않는 경우가 있습니다. 존재하지 않는 소프트웨어 모듈이나 잘못된 Slurm 옵션을 제안하거나, 로그인 노드와 계산 노드의 역할을 혼동할 수 있습니다.

또한 프로그램이 오류 없이 실행되더라도 부적절한 CPU 바인딩, GPU 할당 또는 통신 설정으로 인해 성능이 저하될 수 있습니다. 따라서 AI 모델의 답변보다 실제 시스템에서 확인한 정보와 실행 결과를 우선해야 합니다.

#### 2. 실행 결과 및 성능 검증

AI 코딩 도구가 작성하거나 수정한 프로그램은 다음 사항을 확인하는 것을 권장합니다.

* 프로그램이 오류 없이 종료되고 예상한 결과를 생성하는가?
* 기존 프로그램과 비교하여 계산 결과가 일치하는가?
* CPU, GPU 및 메모리 사용량이 적절한가?
* 파일시스템과 네트워크 사용에 문제가 없는가?
* 변경 전후 성능 차이가 적절한가?
* 모델이 설명한 오류 원인이 실제 로그와 일치하는가?

프로그램이 정상적으로 종료되었다는 사실만으로 계산 결과의 정확성이나 성능이 보장되지는 않습니다. 중요한 계산 작업에서는 정확성 검증과 성능 측정을 별도로 수행해야 합니다.
