# Codex

Codex는 OpenAI에서 제공하는 AI 코딩 도구로, 한강 슈퍼컴퓨터에서 소스코드 작성, 수정, 오류 분석 및 개발 작업을 지원합니다. 본 문서에서는 Codex의 기본 사용 방법과 한강에서 적용되는 안전 설정 및 주의사항을 안내합니다.

{% hint style="warning" %}
**베타서비스 운영 안내**

한강에서 제공하는 Codex의 관리형 안전 설정과 이용 제한은 베타서비스 운영 기간 중 적용되는 사항입니다. 시스템 부하 및 운영 상황에 따라 일부 설정이 변경될 수 있으며, 정식서비스 전환 시 운영 결과를 반영하여 최종 기준이 결정될 수 있습니다.
{% endhint %}

### 가. Codex 개요

Codex는 대규모 언어 모델(LLM)을 기반으로 소스코드를 분석·수정하고, 명령 실행과 테스트를 지원하는 AI 코딩 도구입니다. 사용자의 작업 디렉터리에서 파일을 읽고 수정하며, 실행 결과에 따라 후속 작업을 수행할 수 있습니다.

한강에서는 프로그램 개발, Slurm 작업 스크립트 작성, 실행 오류 분석 및 코드 개선 등에 활용할 수 있습니다. 로그인 노드와 공유 파일시스템을 사용하는 일반적인 원칙은 [AI 코딩 도구 활용 안내](./) 페이지를 참고하시기 바랍니다.

Codex의 다양한 기능과 세부 사용법은 [Codex 공식 사용 설명서](https://developers.openai.com/codex/cli/)를 참고하시기 바랍니다.

### 나. Codex 실행 및 인증

#### 1. 실행 환경

한강에서는 SSH로 로그인 노드에 접속하여 Codex CLI를 사용할 수 있습니다. 접속 방법은 [사용자 환경](https://docs-ksc.gitbook.io/hangang-user-guide/system/user-experience)을 참고하시기 바랍니다.

한강에서는 Codex의 시스템 공용 설치를 제공하지 않으므로 사용자가 자신의 홈 디렉터리에 설치하여 사용해야 합니다. GPU 로그인 노드와 CPU 로그인 노드는 홈 디렉터리를 공유하지만 CPU 아키텍처가 서로 다르므로, 설치한 실행 파일이 다른 노드에서 동작하지 않을 수 있습니다.

먼저 다음 명령으로 현재 아키텍처와 Codex 실행 파일을 확인합니다.

```
uname -m
command -v codex
codex --version
```

설치 및 실행 환경에 문제가 있는 경우에는 다음 명령으로 확인할 수 있습니다.

```
codex doctor
```

설치 및 업데이트에 관한 자세한 사항은 [Codex 공식 설치 안내](https://developers.openai.com/codex/cli/)를 참고하시기 바랍니다.

일부 CPU 로그인 노드에서는 실행 파일이 정상적으로 설치되어 있어도 Codex의 명령 실행 기능에 문제가 발생할 수 있습니다. 해당 증상은 이 문서의 `사. 문제 해결 및 주의사항`을 참고하시기 바랍니다.

#### 2. 사용자 인증

Codex를 사용하려면 별도의 OpenAI 계정 및 이용 권한이 필요합니다. 한강 사용자 계정과 OpenAI 서비스의 인증 및 이용 권한은 별도로 관리됩니다.

Codex를 처음 실행하는 경우 다음 명령으로 시작할 수 있습니다.

```
codex
```

인증되지 않은 상태에서는 로그인 절차가 안내됩니다. ChatGPT 계정으로 인증하려면 다음 명령을 사용할 수 있습니다.

```
codex login
```

한강처럼 원격 터미널에서 웹 브라우저를 직접 사용하기 어려운 환경에서는 장치 코드(Device Code)를 이용한 인증을 사용할 수 있습니다.

```
codex login --device-auth
```

터미널에 표시되는 인증 URL을 사용자 PC의 웹 브라우저에서 열고 OpenAI 계정으로 로그인한 뒤, 안내에 따라 인증을 완료합니다.

장치 코드 인증은 사용자 계정 또는 ChatGPT 워크스페이스의 보안 설정에 따라 제한될 수 있습니다. 해당 기능을 사용할 수 없다면 워크스페이스 관리자에게 문의하거나 [Codex 공식 인증 안내](https://developers.openai.com/codex/auth/)에서 다른 방법을 확인하시기 바랍니다.

인증 상태 확인과 로그아웃은 다음 명령을 이용합니다.

```
codex login status
codex logout
```

OpenAI API를 이용하는 경우에는 별도의 API 인증정보가 필요하며, API 사용량에 따라 요금이 발생할 수 있습니다. API 키와 인증 토큰은 다른 사용자와 공유하거나 프로젝트 파일 및 Git 저장소에 포함하지 않도록 주의해야 합니다.

#### 3. Codex 실행

작업할 프로젝트 디렉터리로 이동한 후 Codex를 실행합니다.

```
cd /scratch/$USER/my-project
codex
```

위 경로는 예시이며 실제 사용자의 프로젝트 디렉터리로 변경해야 합니다. Codex는 실행한 디렉터리를 기준으로 프로젝트 파일을 분석하고 수정할 수 있으므로, 중요한 원본 데이터나 변경해서는 안 되는 파일은 작업 공간과 구분하여 관리하는 것이 좋습니다.

Codex는 VS Code 등 원격 개발 환경에서도 사용할 수 있습니다. **Codex가 한강 로그인 노드에서 실행되면 한강의 관리형 설정이 적용되며, 사용자 PC에서 실행되면 한강 로그인 노드의 관리형 설정이 적용되지 않습니다.**

원격 개발 도구의 사용 가능 여부는 한강의 SSH 및 OTP 인증 방식에 따라 달라질 수 있습니다. 자세한 설정 방법은 [Codex 공식 문서](https://developers.openai.com/codex/cli/)를 참고하시기 바랍니다.

### 다. 기본 사용 및 세션 관리

#### 1. 기본 명령어

Codex는 대화형 세션을 통해 작업을 수행하며, 이전 세션을 다시 불러오거나 새로운 세션을 시작할 수 있습니다.

| 명령어                   | 설명                   |
| --------------------- | -------------------- |
| `codex`               | 새로운 Codex 세션 시작      |
| `codex resume`        | 이전 세션을 선택하여 이어서 실행   |
| `codex resume --last` | 가장 최근에 기록된 세션 이어서 실행 |
| `/status`             | 현재 세션 및 실행 환경 확인     |
| `/permissions`        | 실행 권한과 샌드박스 설정 확인    |
| `/model`              | 사용할 모델 선택            |
| `/compact`            | 대화 내용을 요약하여 컨텍스트 정리  |
| `/review`             | 코드 변경사항 검토           |
| `/init`               | 프로젝트 지침 파일 초기화       |

Codex 실행 중 `/`를 입력하면 사용 가능한 명령 목록을 확인할 수 있습니다. 명령과 기능은 설치 버전에 따라 달라질 수 있습니다.

이전 작업을 이어서 수행하려면 다음 명령을 사용할 수 있습니다.

```
codex resume
```

가장 최근에 기록된 세션을 이어서 실행하려면 다음과 같이 입력합니다.

```
codex resume --last
```

**한강의 Codex 관리형 지침은 새 세션을 시작할 때 적용됩니다.** 운영 지침이 변경된 뒤 이전 세션을 이어서 사용하면 변경 전 지침이 남아 있을 수 있으므로, 지침 변경 후에는 새 세션을 시작하는 것이 좋습니다.

중요한 분석 결과와 작업 내용은 대화 기록에만 의존하지 말고 별도의 파일로 저장하는 것을 권장합니다.

#### 2. 파일 참조 및 컨텍스트 관리

Codex에서는 `@` 기호를 이용하거나 파일 경로를 직접 입력하여 작업 대상을 지정할 수 있습니다.

```
@train.py 파일의 분산학습 초기화 부분을 분석해 줘.

@job.slurm 파일의 자원 할당 설정을 검토해 줘.
```

필요한 파일을 명확히 지정하면 불필요한 파일시스템 탐색을 줄이고 작업에 필요한 정보를 정확하게 제공할 수 있습니다.

많은 대화 내용과 로그가 누적되는 경우에는 `/compact`를 이용하여 컨텍스트를 요약할 수 있습니다. 새로운 작업을 시작하는 경우에는 별도의 세션을 생성하는 것이 좋습니다.

세션 및 명령어에 관한 자세한 내용은 [Codex CLI 참조](https://developers.openai.com/codex/cli/reference/)를 참고하시기 바랍니다.

### 라. 프로젝트별 설정 및 AGENTS.md

#### 1. AGENTS.md 활용

Codex는 `AGENTS.md` 파일을 통해 프로젝트 구조, 개발 환경 및 반복적으로 필요한 작업 지침을 참고할 수 있습니다.

프로젝트 디렉터리에서 Codex를 실행한 뒤 `/init` 명령을 이용하면 초기 `AGENTS.md` 파일을 생성할 수 있습니다.

```
/init
```

생성된 파일에는 디렉터리 구조, 빌드 및 실행 방법, 사용하는 라이브러리, 테스트 절차 및 수정 가능한 파일 범위 등을 기록할 수 있습니다.

한강에서 사용할 프로젝트 지침에는 다음과 같은 내용을 포함하는 것을 권장합니다.

```
# Project Instructions

## Environment
- System: KISTI HANGANG
- Scheduler: Slurm

## Development
- Preserve the existing software environment.
- Do not run heavy workloads on login nodes.
- Avoid broad searches on shared filesystems.
- Confirm before submitting or cancelling Slurm jobs.

## Verification
- Review changes before running tests.
- Use small test cases before large jobs.
- Report modified files and test results.
```

특정 파티션 이름이나 작업 시간처럼 운영 상황에 따라 변경되는 값을 프로젝트 지침에 고정하기보다 실제 시스템 설정과 최신 사용자 지침서를 확인하도록 작성하는 것이 좋습니다.

#### 2. 사용자 및 프로젝트 설정

Codex는 사용자별 공통 지침과 프로젝트별 설정을 지원합니다.

| 설정 파일                  | 용도             |
| ---------------------- | -------------- |
| `~/.codex/AGENTS.md`   | 사용자 공통 작업 지침   |
| 프로젝트의 `AGENTS.md`      | 프로젝트별 작업 지침    |
| `~/.codex/config.toml` | 사용자별 Codex 설정  |
| `.codex/config.toml`   | 프로젝트별 Codex 설정 |

한강에서는 사용자 및 프로젝트 설정과 별도로 기관의 관리형 안전 설정을 적용합니다. 사용자가 작성한 설정이나 `AGENTS.md`는 관리형 설정을 보완하기 위한 것으로, 해당 설정을 변경하거나 우회하는 용도로 사용할 수 없습니다.

`AGENTS.md`의 상세 작성 및 관리 방법은 [Codex 프로젝트 지침 공식 문서](https://developers.openai.com/codex/guides/agents-md/)를 참고하시기 바랍니다.

### 마. 권한 및 안전 설정

#### 1. 샌드박스 및 사용자 승인

Codex는 샌드박스(Sandbox)와 사용자 승인(Approval)을 이용하여 명령 실행과 파일 접근을 제어합니다.

샌드박스는 파일시스템과 네트워크 접근 범위를 제한하는 기능이고, 사용자 승인은 특정 명령의 실행이나 권한 확대 전에 사용자의 확인을 요청하는 기능입니다.

한강에서는 관리형 설정을 통해 다음과 같은 실행 정책을 적용하고 있습니다.

| 항목              | 한강 적용 기준             |
| --------------- | -------------------- |
| 사용자 승인 정책       | `on-request`         |
| 읽기 전용 샌드박스      | `read-only` 허용       |
| 작업 공간 쓰기 샌드박스   | `workspace-write` 허용 |
| 전체 접근 모드        | 허용하지 않음              |
| 승인 절차 및 샌드박스 우회 | 허용하지 않음              |

**읽기 전용(`read-only`)** 모드는 기존 소스코드와 로그를 분석하는 작업에 적합하며, **작업 공간 쓰기(`workspace-write`)** 모드는 지정된 작업 공간에서 파일을 수정하는 일반적인 개발 작업에 적합합니다.

현재 실행 권한은 Codex 세션에서 다음 명령으로 확인할 수 있습니다.

```
/permissions
```

일반적인 개발 작업에서는 기본적으로 제공되는 승인 정책과 샌드박스 설정을 유지하는 것을 권장합니다.

#### 2. 권한 우회 제한 및 Slurm 명령

한강에서는 승인 절차와 샌드박스를 동시에 우회하는 `--dangerously-bypass-approvals-and-sandbox` 및 `--yolo` 등의 실행 방식을 제한하고 있습니다. 사용자 설정이나 실행 옵션을 통해 관리형 정책을 우회해서는 안 됩니다.

또한 현재 한강에서 확인된 Codex의 `workspace-write` 샌드박스 환경에서는 Slurm 명령이 정상 실행되지 않습니다.

`sbatch`, `squeue`, `sacct`, `sinfo` 등의 명령을 샌드박스 안에서 실행하면 다음 오류가 발생할 수 있습니다.

```
Error creating slurm stream socket: Operation not permitted
```

이는 Slurm 클라이언트가 필요한 소켓에 접근하지 못해 발생하는 문제로, 해당 명령을 실행하려면 **Codex가 샌드박스 밖에서 실행할 수 있도록 별도의 사용자 승인을 요청해야 합니다.**

승인하기 전에 실행할 명령, 조회 대상 및 새로 생성되는 작업 수를 확인해야 합니다. 특히 `sbatch`, `scancel` 등 작업 상태를 변경하는 명령은 내용을 충분히 검토한 후 승인하시기 바랍니다.

비대화형 실행(`codex exec`)에서는 사용자 승인을 받을 수 없어 이러한 Slurm 명령이 실패할 수 있습니다. 이 경우 동일한 명령을 반복 실행하기보다 대화형 Codex 세션에서 승인 절차를 거치거나 사용자가 직접 터미널에서 Slurm 명령을 실행해야 합니다.

이 문제는 현재 한강에서 검증한 샌드박스 환경의 동작으로, 모든 Codex 실행 환경에 동일하게 적용되는 일반적인 제한을 의미하지는 않습니다.

권한 및 샌드박스의 상세 설정은 [Codex 권한 및 보안 공식 문서](https://developers.openai.com/codex/sandbox/)를 참고하시기 바랍니다.

#### 3. 한강 운영 지침

다음은 Codex가 따르도록 제공되는 한강의 운영 지침입니다. **아래 명령이나 작업이 모두 기술적으로 자동 차단되는 것은 아닙니다.**

* 공유 파일시스템 상위 디렉터리의 광범위한 탐색 자제
* 로그인 노드에서 장시간·고부하 작업 실행 방지
* 제한 없는 병렬 빌드 및 불필요한 백그라운드 작업 방지
* Slurm 작업 제출·취소 전 사용자 확인
* 반복적인 작업 실패 시 자동 재제출 방지
* 다른 사용자의 파일 및 인증정보 접근 방지
* 기관의 안전 설정을 우회하는 작업 방지

이러한 지침은 Codex의 작업 방식을 안내하기 위한 것으로, 관리형 샌드박스 및 사용자 승인 정책에 따른 기술적 제한과는 구분됩니다.

로그인 노드, 공유 파일시스템 및 Slurm의 자세한 사용 원칙은 **AI 코딩 도구 활용 안내**를 참고하시기 바랍니다.

#### 4. 외부 도구 및 확장 기능

Codex는 MCP(Model Context Protocol) 등을 이용하여 외부 도구와 서비스에 연동할 수 있습니다.

외부 도구를 추가하면 파일 분석, 데이터 조회 및 개발 작업에 필요한 기능을 확장할 수 있지만, 해당 도구에 부여된 권한에 따라 파일 접근과 데이터 전송 범위가 확대될 수 있습니다.

따라서 신뢰할 수 있는 도구만 사용하고, 기관의 보안 요구사항이나 관리형 설정을 우회하기 위한 목적으로 사용하지 않아야 합니다.

MCP 및 기타 확장 기능의 사용 방법은 [Codex 공식 문서](https://developers.openai.com/codex/cli/)를 참고하시기 바랍니다.

### 바. Codex 활용 예제

#### 1. 소스코드 분석

Codex를 이용하여 기존 프로그램의 구조와 주요 함수의 역할을 분석할 수 있습니다.

```
@src/ 디렉터리의 코드 구조를 분석하고
MPI 초기화와 통신을 담당하는 부분을 정리해 줘.

코드는 수정하지 말고 분석 결과만 설명해 줘.
```

공유 파일시스템의 상위 디렉터리를 탐색하도록 요청하기보다 분석할 프로젝트와 파일 범위를 명확히 지정하는 것이 좋습니다.

#### 2. Slurm 작업 스크립트 검토

Codex는 기존 Slurm 작업 스크립트의 자원 할당과 실행 명령을 검토할 수 있습니다.

```
@job.slurm 파일을 검토해 줘.

한강 사용자 지침서의 Slurm 사용 방법과 비교하여
잘못된 옵션이나 개선할 부분을 설명해 줘.

실제 작업은 제출하지 말고
수정이 필요한 부분만 제안해 줘.
```

Codex가 제안한 Slurm 옵션은 현재 시스템에서 지원되는지 확인해야 합니다. 실제 Slurm 명령을 실행할 때에는 샌드박스 제약과 사용자 승인 절차를 확인해야 합니다.

#### 3. 프로그램 오류 분석 및 수정

프로그램이 정상적으로 실행되지 않는 경우에는 작업 스크립트와 오류 로그를 함께 제공하여 원인을 분석할 수 있습니다.

```
@job.slurm 작업이 실행 직후 종료되었습니다.

오류 로그를 분석하여 가능한 원인을 우선순위별로 정리해 줘.

기존 실행 환경을 유지하면서 최소한의 수정사항과
검증 방법을 제안해 줘.

새로운 Slurm 작업은 제출하지 마.
```

코드를 수정한 경우에는 변경사항을 검토하고 작은 입력 데이터로 정상 동작을 확인한 뒤 실제 계산 작업에 적용하는 것이 좋습니다.

#### 4. 코드 변경사항 검토

Codex는 Git 저장소에서 변경된 코드를 분석하고 문제점을 검토할 수 있습니다.

대화형 세션에서는 다음 명령을 사용할 수 있습니다.

```
/review
```

터미널에서는 다음 명령으로 코드 검토를 수행할 수 있습니다.

```
codex review
```

코드 검토는 변경으로 인한 오류, 기존 동작과의 호환성 및 테스트 누락 등을 확인하는 데 활용할 수 있습니다. 다만 실제 실행 검증을 대체하지는 않으므로 중요한 변경사항은 컴파일과 테스트를 통해 확인해야 합니다.

### 사. 문제 해결 및 주의사항

#### 1. 주요 문제 및 확인 방법

| 증상                                      | 확인 사항                                  |
| --------------------------------------- | -------------------------------------- |
| `codex: command not found`              | 사용자 설치 여부 및 PATH 설정                    |
| Codex 실행 불가                             | 실행 파일과 시스템 아키텍처의 호환성 확인                |
| 로그인 또는 인증 실패                            | OpenAI 계정 이용 권한 및 인증 상태 확인             |
| 장치 코드 인증 실패                             | ChatGPT 계정 또는 워크스페이스의 인증 허용 여부 확인      |
| 명령 실행이 제한됨                              | 현재 승인 정책 및 샌드박스 설정 확인                  |
| Slurm 명령에서 `Operation not permitted` 오류 | 샌드박스의 Slurm 소켓 접근 제한 확인                |
| CPU 로그인 노드에서 `closed its stdout` 오류     | 현재 확인된 Codex 명령 실행 문제. GPU 로그인 노드에서 사용 |
| 이전 세션에서 변경된 지침이 반영되지 않음                 | 새 Codex 세션 시작                          |
| 원격 환경에서 설정이 다름                          | Codex가 실제로 실행되는 호스트 확인                 |

설치 및 실행 환경에 문제가 발생한 경우에는 `codex doctor` 명령으로 상태를 확인할 수 있습니다.

#### 2. CPU 로그인 노드의 명령 실행 문제

현재 한강의 CPU 로그인 노드(`clogin`)에서는 Codex가 명령 실행 도구를 사용할 때 `closed its stdout` 오류가 발생하는 문제가 확인되어 있습니다.

동일한 x86\_64 아키텍처의 데이터 이동 노드에서는 정상 실행된 사례가 있으므로, 단순한 실행 파일 아키텍처 불일치로 판단해서는 안 됩니다.

이 문제는 Codex의 명령 실행 환경과 관련된 것으로, 사용자 코드 또는 Slurm 작업 스크립트의 오류와 구분해야 합니다. 현재 해당 증상이 발생하면 **GPU 로그인 노드에서 Codex를 사용**하시기 바랍니다.

관련 문제는 [Codex GitHub Issue #53091](https://github.com/openai/codex/issues/53091)에서 확인할 수 있습니다. 해당 사항은 향후 Codex 및 한강 시스템 환경 변경에 따라 해결될 수 있습니다.

#### 3. 이용 시 주의사항

Codex는 사용자의 계정과 권한으로 파일을 수정하고 명령을 실행합니다. 따라서 중요한 파일이나 연구 데이터가 의도하지 않게 변경되지 않도록 관리하고, 실행 결과의 정확성과 성능을 검증해야 합니다.

대규모 디렉터리 탐색, 반복적인 Slurm 작업 제출 및 장시간 백그라운드 실행은 공유 시스템에 영향을 줄 수 있으므로 주의해야 합니다.

관리형 설정에 의해 제한된 기능을 사용자 설정이나 별도의 실행 방법으로 우회해서는 안 됩니다.
